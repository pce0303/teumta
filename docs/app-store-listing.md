> 실제 동작과 다른 설명은 이용자 신뢰 문제이기도 하다.

## 부제 (Subtitle, 30자 이내)

```
혼잡한 관광지, 근처부터 둘러보기
```

## 프로모션 텍스트 (Promotional Text, 170자 이내)

기능을 나열하지 않고 브랜드 톤으로 쓴다. **심사 없이 언제든 바꿀 수 있는 칸**이라
계절·이벤트에 맞춰 교체하기 좋다.

```
붐비는 곳을 비켜, 여행은 그대로. 가려던 곳이 붐빈다면 걸어서 가까운 곳부터 둘러보세요. 틈타가 내 시간에 맞는 로컬 코스와 돌아갈 순간을 함께 찾아드려요.
```

교체용 대안:

```
붐비는 순간에도 여행은 이어집니다. 가려던 곳이 붐빈다면, 걸어서 닿는 곳부터 둘러보세요. 틈타가 시간에 맞는 로컬 코스와 돌아갈 순간을 찾아드려요.
```

## 설명 (Description)

```
붐비는 관광지 앞에서, 걸어서 갈 수 있는 근처로

가고 싶었던 관광지에 도착했는데 사람이 너무 많다면 어떻게 하시나요?

한참을 기다리거나 발길을 돌리기 전에, 틈타보세요.

틈타는 관광지가 지금 얼마나 붐비는지 확인하고, 여유가 있는 만큼의 시간에 맞춰 걸어서 다녀올 수 있는 근처를 둘러보는 우회 코스를 만들어 드립니다. 실제 보행 경로로 계산하고, 원래 가려던 곳으로 언제 돌아오면 되는지까지 함께 보여드려요.

관광객이 한곳에 몰려 있는 사이, 걸어서 몇 분 거리의 미술관과 밥집, 작은 상점은 한산합니다. 틈타는 그 사이를 이어 여행이 끊기지 않게 합니다.

■ 지금 얼마나 붐비는지 확인
방문하려는 관광지의 실시간 혼잡도를 확인해보세요. (혼잡도 정보가 제공되는 관광지에 한해 표시됩니다)

■ 덜 붐비는 날 고르기
앞으로 30일간의 날짜별 관광지 집중률을 참고해 방문 날짜를 정할 수 있어요.

■ 시간에 맞춘 우회 코스
30분, 60분, 90분 — 쓸 수 있는 시간을 고르면 그 안에 다녀올 수 있는 코스를 만들어 드려요. 걷는 시간은 실제 보행 경로로 계산합니다.

■ 걸어서 닿는 로컬 장소
유명 관광지만 보고 지나쳤다면 몰랐을 근처의 문화시설, 밥집, 상점을 만나보세요.

■ 돌아갈 시간 안내
우회의 끝은 새로운 목적지가 아닙니다. 처음 가려던 곳으로 돌아갈 예상 시각을 코스와 함께 보여드려요.

■ 로그인 없이, 위치는 기기 안에서만
회원가입이 필요 없습니다. 현재 위치는 도착 여부를 확인하는 데만 쓰이며 기기 밖으로 나가지 않습니다.

붐비는 곳을 피해 여행을 포기하는 대신,
그 사이의 틈을 새로운 여행으로 바꿔보세요.

틈타 — 붐비는 시간은 비켜가고, 여행은 그대로.

출처: ⓒ한국관광공사
```

## 이전 문구에서 바꾼 점과 이유

| 바뀐 것 | 이유 |
|---|---|
| "기다리는 시간을 여행으로" → "붐비는 관광지 앞에서, 걸어서 갈 수 있는 근처로" | 서비스의 문제의식이 **시간 때우기**가 아니라 **한곳에 몰린 관광객을 주변으로 분산**하는 것이다. 대표 문구가 방향을 정한다 |
| 로컬 상권을 명시(문화시설·밥집·상점) | 우회 코스가 실제로 음식점·쇼핑·문화시설을 후보로 삼는다. 분산의 수혜자가 누구인지 드러난다 |
| **"골목" 표현 삭제 → "걸어서 갈 수 있는 근처"** | 실제 추천 결과는 골목이 아니다. 경복궁 주변은 국립현대미술관·세종문화회관 같은 대형 문화시설이 나오고, 성산일출봉처럼 골목이랄 게 없는 곳도 대상이다. "골목"은 서울 원도심으로 범위를 좁혀 전국 서비스라는 사실과 어긋난다 |
| "덜 붐비는 날 고르기" 항목 추가 | 30일 집중률 예측은 실제 기능인데 이전 문구에 빠져 있었다. 여행 **전** 단계의 분산이라 서사에도 맞는다 |
| "실제 보행 경로로 계산" 문구 추가 | 직선거리가 아니라 실제 도보 경로로 계산한다. 경쟁 앱과 구분되는 지점 |
| 혼잡도에 "제공되는 관광지에 한해" 단서 | 모든 관광지에 실시간 혼잡도가 있지 않다. 과장하면 리젝 사유가 된다 |
| **"복귀 10분 전에 알려드려요" 삭제** | **알림 기능이 구현돼 있지 않다.** 없는 기능을 설명에 쓰면 안 된다(앱 내 문구도 함께 수정) |
| 로그인 불필요·위치 미전송 명시 | 심사에서 유리하고, 우리 아키텍처의 실제 강점이다 |

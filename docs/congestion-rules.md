# 혼잡도 판단 기준 초안

## 1. 문서 목적

틈타 서비스에서 여행 전 확인하는 날짜별 예상 관광지 집중률과 여행 당일 확인하는 실시간 장소 혼잡도를 구분하고, 각 데이터의 활용 기준을 정의한다.

또한 실시간 혼잡도가 높은 경우 저장된 Route를 활용해 우회 코스를 추천하고, TMAP으로 실제 이동시간과 예상 복귀 시각을 계산하는 초기 기준을 정리한다.

본 문서는 초기 설계안이며, 한국관광공사 관광지 집중률 예측 데이터와 SK 장소 혼잡도 데이터의 실제 응답 형식, 값의 범위 및 제공 단위를 확인한 후 세부 기준을 수정한다.

---

## 2. 혼잡도 데이터 구분

백엔드의 `CongestionType` 구조와 동일하게 혼잡도 데이터를 두 종류로 구분한다.

| 구분 | 의미 | 데이터 소스 | 주요 활용 시점 |
|---|---|---|---|
| PREDICTED | 특정 미래 날짜의 예상 관광지 집중률 | 한국관광공사 관광지 집중률 예측 데이터 | 여행 전 |
| REALTIME | 현재 시점의 장소 혼잡도 | SK 장소 혼잡도 데이터 | 여행 당일 |

### PREDICTED

`PREDICTED`는 특정 미래 시각이나 시간대의 예상 혼잡도가 아니라, 특정 미래 날짜의 예상 관광지 집중률을 의미한다.

한국관광공사 관광지 집중률 예측 데이터를 기반으로 방문 예정일의 관광지 집중 수준을 제공한다.

현재 확인된 KTO 데이터는 특정 시각이나 시간대별 미래 혼잡도를 제공하는 데이터가 아니므로 다음 용도로는 사용하지 않는다.

- 같은 날짜 내 시간대별 혼잡도 비교
- 특정 미래 시각의 혼잡도 예측
- 복귀 예정 시점의 혼잡도 예측

### REALTIME

`REALTIME`은 현재 시점에 측정된 장소 혼잡도를 의미한다.

SK 장소 혼잡도 데이터를 기반으로 여행 당일 현재 관광지의 혼잡 상태를 판단한다.

REALTIME 데이터는 현재 혼잡 상태를 판단하는 데 사용하며, 미래 특정 시점의 혼잡도를 예측하는 값으로 사용하지 않는다.

## 3. 혼잡도 단계

백엔드의 `CongestionLevel` 구조와 동일하게 다음 네 단계를 사용한다.

| 단계 | 의미 | 사용자 안내 예시 |
|---|---|---|
| RELAXED | 여유 | 현재 비교적 여유로운 상태입니다. |
| NORMAL | 보통 | 방문객이 있지만 이용 가능한 상태입니다. |
| CROWDED | 혼잡 | 현재 혼잡하여 우회 코스를 확인할 수 있습니다. |
| VERY_CROWDED | 매우 혼잡 | 현재 매우 혼잡하여 우회 코스를 우선 추천합니다. |

위 사용자 안내 문구와 혼잡도 단계는 현재 혼잡 상태를 보여주는 `REALTIME` 데이터를 중심으로 사용한다.

백엔드의 `Congestion.level` 필드는 nullable로 정의되어 있으므로, 모든 외부 데이터에 반드시 `CongestionLevel`을 부여하지 않는다.

KTO 관광지 집중률 예측 데이터는 공식적인 혼잡도 등급 임계값을 제공하지 않으므로, 공식 기준 없이 임의로 `RELAXED`, `NORMAL`, `CROWDED`, `VERY_CROWDED` 단계를 생성하지 않는다.

KTO 데이터의 원본 집중률 값은 `Congestion.concentrationRate`에 저장하고, `level`은 null로 저장한다.

```text
KTO 원본 concentrationRate
→ concentrationRate에 원본값 저장
→ level은 null로 저장

SK 원본 데이터
→ 실제 API 응답 형식 확인
→ SK 전용 mapping 기준 정의
→ CongestionLevel
```

KTO 관광지 집중률과 SK 장소 혼잡도의 원본 데이터는 값의 범위, 의미 및 산정 기준이 서로 다르므로 직접 비교하지 않는다.

또한 두 데이터 소스에 동일한 점수 구간이나 공통 threshold를 적용하지 않는다.

SK 장소 혼잡도 데이터의 `level`, `score`, `measuredAt` 저장 기준은 실제 API 응답의 단계, 점수 범위 및 측정 시각 제공 여부를 확인한 후 확정한다.

추후 KTO 데이터의 값 범위와 분포를 충분히 확인하고 팀에서 별도의 기준을 확정한 경우에만 KTO 전용 `CongestionLevel` mapping 적용 여부를 검토한다.
